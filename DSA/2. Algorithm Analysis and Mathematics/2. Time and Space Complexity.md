## PART 2: Time Complexity and Space Complexity

### 2.1 What is Complexity Analysis?

Complexity analysis quantifies the efficiency of an algorithm by measuring the growth rate of computational resources needed as input size ($n$) scales towards infinity.

1. **Time Complexity:** The rate of growth of basic operations performed.
2. **Space Complexity:** The rate of growth of total memory (primary focus: auxiliary working memory) allocated.

---

### 2.2 Time Complexity Illustrated

Time complexity abstracts hardware, clock frequencies, and compiler variations to express operation counts strictly as a function of input size $n$.

#### Example 1: Constant Time – $\mathcal{O}(1)$

```java
int a = 10;
System.out.println(a);
```

Executes a fixed number of operations independent of any input magnitude.

$$\text{Time Complexity} = \mathcal{O}(1)$$

#### Example 2: Linear Time – $\mathcal{O}(n)$

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

The loop statement executes directly in proportion to $n$.

$$\text{Time Complexity} = \mathcal{O}(n)$$

#### Example 3: Quadratic Time – $\mathcal{O}(n^2)$

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + " " + j);
    }
}
```

For every step of the outer loop ($n$), the inner loop executes $n$ times: $n \times n = n^2$.

$$\text{Time Complexity} = \mathcal{O}(n^2)$$

#### Example 4: Logarithmic Time – $\mathcal{O}(\log n)$

```java
int i = 1;
while (i < n) {
    i = i * 2;
}
```

The loop variable doubles each round: $1, 2, 4, 8, \dots, 2^k$. It terminates when $2^k \ge n \implies k = \lceil\log_2 n\rceil$.

$$\text{Time Complexity} = \mathcal{O}(\log n)$$

#### Example 5: Linearithmic Time – $\mathcal{O}(n \log n)$

Subdivides problem into $\log n$ recursive levels, performing $\mathcal{O}(n)$ work across each level (e.g., Merge Sort).

$$\text{Time Complexity} = \mathcal{O}(n \log n)$$

### 2.3 Common Time Complexities

| Notation                | Classification | Typical Example                                       |
| :---------------------- | :------------- | :---------------------------------------------------- |
| $\mathcal{O}(1)$        | Constant       | Array element lookup by direct index                  |
| $\mathcal{O}(\log n)$   | Logarithmic    | Binary Search in a sorted array                       |
| $\mathcal{O}(n)$        | Linear         | Linear search, single loop iteration                  |
| $\mathcal{O}(n \log n)$ | Linearithmic   | Merge Sort, Heap Sort                                 |
| $\mathcal{O}(n^2)$      | Quadratic      | Bubble Sort, Selection Sort, nested double loops      |
| $\mathcal{O}(n^3)$      | Cubic          | Matrix multiplication (standard), nested triple loops |
| $\mathcal{O}(2^n)$      | Exponential    | Naive recursive Fibonacci computation                 |
| $\mathcal{O}(n!)$       | Factorial      | Generating all permutations of an array/string        |

### 2.4 Complexity Growth Comparison

Comparative operation volume as a function of $n = 10$:

| Complexity                | Theoretical Operations ($n = 10$) | Growth Severity                |
| :------------------------ | :-------------------------------- | :----------------------------- |
| $\mathcal{O}(1)$          | $1$                               | Excellent                      |
| $\mathcal{O}(\log_2 n)$   | $\approx 4$                       | Excellent                      |
| $\mathcal{O}(n)$          | $10$                              | Fair                           |
| $\mathcal{O}(n \log_2 n)$ | $\approx 33$                      | Good / Manageable              |
| $\mathcal{O}(n^2)$        | $100$                             | Moderate / Poor for large $n$  |
| $\mathcal{O}(n^3)$        | $1,000$                           | Heavy                          |
| $\mathcal{O}(2^n)$        | $1,024$                           | Infeasible for practical scale |
| $\mathcal{O}(n!)$         | $3,628,800$                       | Extremely intractable          |

$$\mathcal{O}(1) < \mathcal{O}(\log n) < \mathcal{O}(n) < \mathcal{O}(n \log n) < \mathcal{O}(n^2) < \mathcal{O}(n^3) < \mathcal{O}(2^n) < \mathcal{O}(n!)$$

### 2.5 Best, Average, and Worst Case

Algorithms behave differently depending on input permutations of equal size $n$:

- **Best Case:** The minimum number of steps required for a given input size.
  - _Example:_ Linear Search when the search target resides at index $0 \implies \mathcal{O}(1)$.
- **Average Case:** The expected steps taken across an evenly distributed, randomized sample of inputs.
  - _Example:_ Linear Search over uniform target locations $\implies \mathcal{O}(n)$.
- **Worst Case:** The absolute maximum number of steps an algorithm can take for input size $n$.
  - _Example:_ Linear Search when the key is at the last index or not present $\implies \mathcal{O}(n)$.

### 2.6 Asymptotic Notations

Asymptotic notations provide a formal mathematical language for describing the bounding curves of runtime functions $f(n)$.

```
   Time
    ^                 f(n) <= c * g(n)
    |                       /
    |                      /  c * g(n) [Upper Bound]
    |                     /
    |            *-------/
    |           / \     /
    |          /   *---/----- f(n)
    |         /       /
    |        /       /
    +-------+-------+-----------------> Input Size (n)
           n0
```

#### 1. Big O Notation – $\mathcal{O}(g(n))$

- **Asymptotic Upper Bound:** Defines the ceiling of growth rate.
- Formal condition: $f(n) \le c \cdot g(n)$ for all $n \ge n_0$, where $c > 0$ and $n_0 \ge 1$.
- _Example:_ If $f(n) = 3n^2 + 5n + 10$, then $f(n) = \mathcal{O}(n^2)$.

#### 2. Big Omega Notation – $\Omega(g(n))$

- **Asymptotic Lower Bound:** Defines the floor of growth rate.
- Formal condition: $f(n) \ge c \cdot g(n)$ for all $n \ge n_0$, where $c > 0$ and $n_0 \ge 1$.
- _Example:_ If $f(n) = 3n^2 + 5n + 10$, then $f(n) = \Omega(n^2)$.

#### 3. Big Theta Notation – $\Theta(g(n))$

- **Tight Asymptotic Bound:** Bound that is both an upper and lower bound simultaneously.
- Formal condition: $c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ for all $n \ge n_0$, where $c_1, c_2 > 0$ and $n_0 \ge 1$.
- _Example:_ If $f(n) = 3n^2 + 5n + 10$, then $f(n) = \Theta(n^2)$.

> **Exam Alert:** Do not confuse bounds with cases. An algorithm can have a Big-O, Omega, and Theta bound for its _worst-case_, _best-case_, or _average-case_ function individually.

### 2.7 Rules for Calculating Time Complexity

#### Rule 1: Drop Multiplicative Constants

Constant coefficients do not change the asymptotic rate of growth:

$$\mathcal{O}(c \cdot f(n)) \implies \mathcal{O}(f(n))$$

$$\mathcal{O}(5n) = \mathcal{O}(n)$$

#### Rule 2: Ignore Non-Dominant (Lower Order) Terms

Keep only the term that grows fastest as $n \to \infty$:

$$\mathcal{O}(n^2 + 100n + 500) = \mathcal{O}(n^2)$$

#### Rule 3: Add Consecutive Statements

When blocks execute sequentially, add their complexities and retain the maximum:

```java
for (int i = 0; i < n; i++) {       // O(n)
    System.out.println(i);
}

for (int j = 0; j < n; j++) {       // O(n)
    System.out.println(j);
}
```

$$\mathcal{O}(n) + \mathcal{O}(n) = \mathcal{O}(2n) \implies \mathcal{O}(n)$$

#### Rule 4: Multiply Nested Loops

Multiply the iteration domains when loops are nested:

```java
for (int i = 0; i < n; i++) {           // Runs n times
    for (int j = 0; j < n; j++) {       // Runs n times per outer loop
        System.out.println(i + j);
    }
}
```

$$\mathcal{O}(n \times n) = \mathcal{O}(n^2)$$

#### Rule 5: Logarithmic Halving

Whenever loop progress divides or multiplies by a factor $k > 1$ each iteration:

```java
while (n > 1) {
    n = n / 2;
}
```

$$\mathcal{O}(\log_2 n)$$

### 2.8 Space Complexity

**Space complexity** measures the total memory required by the algorithm relative to input size $n$.

$$\text{Total Space} = \text{Fixed Part (Code, Constants)} + \text{Variable Part (Input + Auxiliary Dynamic Memory)}$$

- **Auxiliary Space:** Extra temporary working memory allocated by the algorithm outside the original input payload.

#### Example 1: Constant Auxiliary Space – $\mathcal{O}(1)$

```java
int a = 10;
int b = 20;
int sum = a + b;
```

Uses a fixed number of localized primitive variables. $\text{Auxiliary Space} = \mathcal{O}(1)$.

#### Example 2: Linear Auxiliary Space – $\mathcal{O}(n)$

```java
int[] arr = new int[n];
```

Allocates a new heap array directly proportional to $n$. $\text{Auxiliary Space} = \mathcal{O}(n)$.

#### Example 3: Call Stack Recursive Space – $\mathcal{O}(n)$

```java
static void print(int n) {
    if (n == 0) return;
    print(n - 1);
}
```

Each recursive invocation pushes a stack frame onto the thread's call stack. With a recursion depth of $n$, this requires $\mathcal{O}(n)$ auxiliary stack frames.
