# Module 02: Object-Oriented Programming (OOP) in Java

## Unit 2.2: Constructors and Object Initialization

### 1. Introduction to Constructors

A **constructor** is a specialized block of code invoked implicitly when an object is instantiated using the `new` keyword. Its primary responsibility is to transition an object from an uninitialized, raw zero-filled state on the Heap to a valid, consistent domain state.

```
                  Object Lifecycle Initialization Pipeline
                                      │
         ┌────────────────────────────┴────────────────────────────┐
         ▼                                                         ▼
Phase 1: Memory Allocation                                Phase 2: Constructor (<init>)
- Heap memory allocated                                   - super() chaining
- Object Header populated (Mark/Klass Words)              - Instance Initializer Blocks
- Instance fields zero-filled (0, false, null)           - Constructor body statements

```

#### 1.1 Structural Invariants of Constructors

1. **Name Matching:** A constructor's identifier **must match the enclosing class name** verbatim (including exact case).

2. **No Return Type:** A constructor must **never declare a return type**, not even `void`. If a return type is specified, the compiler silently treats it as a standard **method**, not a constructor.

3. **Applicable Access Modifiers:** Can be declared `public`, `protected`, package-private (default), or `private`.

4. **Prohibited Modifiers:** Cannot be declared `static`, `final`, `abstract`, `synchronized`, or `native`.

5. **Bytecode Representation:** At the JVM bytecode level, every Java constructor is compiled into an instance initialization method named **`<init>`**.

```
public class Box {
    // Constructor (<init>)
    public Box() {
        System.out.println("Box constructor invoked");
    }

    // METHOD TRAP: Returns void; NOT a constructor!
    public void Box() {
        System.out.println("WARNING: This is a standard method named Box!");
    }
}

```

### 2. Default Constructor vs. No-Argument Constructor

A common source of confusion in examinations and interviews is the precise distinction between a **default constructor** and a **user-defined no-argument constructor**.

```
                           Constructors with No Parameters
                                         │
         ┌───────────────────────────────┴───────────────────────────────┐
         ▼                                                               ▼
Default Constructor (Compiler-Synthesized)            User-Defined No-Arg Constructor
- Generated ONLY if zero constructors exist           - Explicitly authored in source code
- Source code contains NO constructors at all         - May contain custom initialization logic
- Modifiers match the class access modifier           - Modifiers chosen explicitly by programmer
- Body contains ONLY a single super(); call           - Executes custom logic after super()

```

#### 2.1 The Default Constructor Invariant

If (and **only if**) a class declares **no constructors whatsoever**, the Java compiler (`javac`) synthesizes a public or package-private no-argument constructor called the **Default Constructor**.

```
// Source Code:
public class Vehicle {
    // Zero constructors written by developer
}

// Bytecode generated by javac (Decompiled view):
public class Vehicle {
    public Vehicle() {
        super(); // Implicit call to java.lang.Object.<init>()
    }
}

```

> ⚠️ **The Disappearing Default Constructor Trap:**
> As soon as you declare **any constructor** (such as a parameterized constructor), the compiler **completely revokes** the synthetic default constructor. Attempting to call `new ClassName()` without explicitly declaring a no-arg constructor will cause a **compile-time error**.

```
class Student {
    int id;
    Student(int id) { this.id = id; } // Parameterized constructor provided
}

public class Main {
    public static void main(String[] args) {
        // COMPILE ERROR: constructor Student in class Student cannot be applied to given types;
        // required: int; found: no arguments; reason: actual and formal argument lists differ in length
        Student s = new Student();
    }
}

```

### 3. Parameterized Constructors

A parameterized constructor accepts arguments to initialize instance variables with specific data values during instantiation.

```
public class Product {
    private final String sku;
    private double price;

    public Product(String sku, double price) {
        if (price < 0.0) {
            throw new IllegalArgumentException("Price cannot be negative");
        }
        this.sku = sku;
        this.price = price;
    }
}

```

### 4. Constructor Overloading

**Constructor Overloading** is the practice of declaring multiple constructors within the same class, each differentiated by its **parameter list** (differing argument count, types, or relative ordering).

```
public class Dimension {
    private int width;
    private int height;
    private int depth;

    // Overload 1: Default dimensions
    public Dimension() {
        this(1, 1, 1); // Delegate to Overload 3
    }

    // Overload 2: Cube
    public Dimension(int side) {
        this(side, side, side); // Delegate to Overload 3
    }

    // Overload 3: Full Cuboid
    public Dimension(int w, int h, int d) {
        this.width = w;
        this.height = h;
        this.depth = d;
    }
}

```

### 5. Constructor Chaining (`this()` and `super()`)

**Constructor Chaining** is the mechanism where one constructor invokes another constructor in the same class (via `this()`) or in the direct superclass (via `super()`).

```
                    Constructor Chaining Hierarchy
                                  │
         ┌────────────────────────┴────────────────────────┐
         ▼                                                 ▼
Same-Class Chaining: this(...)                    Superclass Chaining: super(...)
- Invokes overloaded constructor in current class - Invokes constructor of immediate parent
- Eliminates redundant initialization code        - Ensures base state is fully constructed
- MUST be the FIRST statement in constructor      - MUST be the FIRST statement in constructor

```

#### 5.1 Strict Rules for `this()` and `super()`

1. **The First Statement Rule:** Either `this(...)` or `super(...)` **must be the very first statement** in a constructor body.

2. **Mutual Exclusion:** A constructor **cannot contain both** `this()` and `super()`. Calling `this()` delegates to another constructor, which will ultimately invoke `super()`.

3. **Implicit `super()` Insertion:** If a constructor contains neither `this()` nor `super()`, the compiler automatically injects an implicit parameterless **`super();`** as the first statement.

4. **No Recursive Chaining:** Constructors must not form circular invocation paths (compile-time error: _recursive constructor invocation_).

```
class IllegalChaining {
    IllegalChaining() {
        this(10); // Error if circular
    }
    IllegalChaining(int x) {
        this();   // COMPILE ERROR: recursive constructor invocation
    }
}

```

### 6. The `this` Keyword

`this` is an implicit reference variable present inside all non-static methods and constructors. It points directly to the **current object instance** whose method or constructor is executing.

```
STACK FRAME (Constructor)                           HEAP MEMORY
┌──────────────────────────────┐                   ┌──────────────────────────────┐
│ this: 0x44A0 ────────────────┼─────────────────► │ Account Object (0x44A0)      │
│ id: 101                      │                   ├──────────────────────────────┤
└──────────────────────────────┘                   │ id: 101                      │
                                                   └──────────────────────────────┘

```

#### 6.1 Primary Use Cases of `this`:

1. **Shadowing Resolution (Disambiguation):** Distinguishes instance fields from method/constructor parameters with identical identifiers:

   ```
   public void setId(int id) {
       this.id = id; // 'this.id' is the instance field; 'id' is the local parameter
   }

   ```

2. **Explicit Constructor Delegation:** Calling `this(args...)` to invoke overloaded constructors.

3. **Passing Current Instance:** Passing the calling object as a callback or parameter to other methods:

   ```
   eventDispatcher.registerListener(this);

   ```

4. **Method Chaining (Fluent Builder Pattern):** Returning `this` from mutator methods:

   ```
   public Builder setName(String name) {
       this.name = name;
       return this; // Allows: builder.setName("A").setAge(20)
   }

   ```

### 7. The `super` Keyword

`super` is a reference variable used in subclasses to access members (fields, methods, constructors) of the immediate **superclass**.

#### 7.1 Primary Use Cases of `super`:

1. **Superclass Constructor Invocation:** Calling `super(args...)` to pass initialization parameters upward.

2. **Un-hiding Shadowed Superclass Fields:** Accessing a base class field hidden by a subclass field with the same name:

   ```
   class Base { int code = 10; }
   class Sub extends Base {
       int code = 20;
       void print() {
           System.out.println(super.code); // Prints: 10
           System.out.println(this.code);  // Prints: 20
       }
   }

   ```

3. **Bypassing Method Overrides:** Calling the superclass version of an overridden method:

   ```
   @Override
   public void render() {
       super.render(); // Execute base rendering logic first
       applySubclassFilters();
   }

   ```

### 8. Instance Initializer Blocks (IIB)

An **Instance Initializer Block (IIB)** is a block of code enclosed in curly braces `{ }` declared directly inside a class body, outside any method or constructor.

```
public class Device {
    private int serialNumber;

    // Instance Initializer Block (IIB)
    {
        serialNumber = (int)(Math.random() * 1000000);
        System.out.println("IIB executed: Serial assigned");
    }

    public Device() {
        System.out.println("No-arg constructor executed");
    }

    public Device(int customId) {
        this.serialNumber = customId;
        System.out.println("Parameterized constructor executed");
    }
}

```

#### 8.1 How the Compiler Lowers IIBs (Bytecode Mechanics)

The Java compiler does **not** execute IIBs as independent methods. Instead:

1. `javac` copies the contents of all IIBs directly into **every single constructor** of that class.

2. The code is placed **immediately after the call to `super(...)`** and **immediately before the constructor's own body statements**.

3. If a constructor delegates using `this(...)`, the IIB is **not** copied into that delegating constructor; it is executed only once by the target constructor that ultimately calls `super()`.

### 9. Static Initializer Blocks (`<clinit>`)

A **Static Initializer Block** is declared using the `static { }` keyword combination. It is used to initialize `static` fields and perform one-time class configuration.

```
public class DatabasePool {
    static Connection sharedConnection;

    static {
        try {
            sharedConnection = DriverManager.getConnection("jdbc:h2:mem:test");
            System.out.println("Static Block: Connection established");
        } catch (SQLException e) {
            throw new ExceptionInInitializerError(e);
        }
    }
}

```

#### 9.2 Key Invariants of Static Blocks:

1. **Execution Timing:** Executed **exactly once** when the class is loaded and initialized by the ClassLoader in Metaspace.

2. **Instance Independence:** Runs before any object of that class is constructed, and before any static method of that class is called.

3. **No `this` or `super`:** Cannot access instance variables or use `this`/`super` because no instance exists yet.

4. **Bytecode Container:** All static variable assignments and static blocks are aggregated in order into the class initialization method: **`<clinit>`**.

### 10. The Complete Object Initialization Order (The 11-Step Lifecycle)

When the JVM executes `new Derived()`, it follows this strict 11-step sequence:

```
               Complete Object Initialization Timeline
                                  │
   ┌──────────────────────────────┴──────────────────────────────┐
   │ STEP 1: Class Loading (Metaspace Check)                     │
   │ 1. Load BaseClass -> Execute BaseClass static blocks        │
   │ 2. Load DerivedClass -> Execute DerivedClass static blocks  │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
   ┌──────────────────────────────┴──────────────────────────────┐
   │ STEP 2: Heap Memory Allocation & Zeroing                    │
   │ 3. Allocate bytes on Heap (Headers + Base & Derived fields) │
   │ 4. Zero-fill all fields (0, 0.0, false, null)               │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
   ┌──────────────────────────────┴──────────────────────────────┐
   │ STEP 3: Base Class Initialization                           │
   │ 5. Enter Derived constructor -> Jump to super()             │
   │ 6. Enter Base constructor -> Jump to Object()               │
   │ 7. Execute Base Class field initializers & IIBs             │
   │ 8. Execute Base Class constructor body                      │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
   ┌──────────────────────────────┴──────────────────────────────┐
   │ STEP 4: Derived Class Initialization                        │
   │ 9. Execute Derived Class field initializers & IIBs          │
   │ 10. Execute Derived Class constructor body                  │
   │ 11. Return reference pointer to caller                      │
   └─────────────────────────────────────────────────────────────┘

```

#### 10.1 Definitive Code Verification Trace

```
class Base {
    static { System.out.println("1. Base Static Block"); }

    { System.out.println("3. Base IIB"); }

    Base() {
        System.out.println("4. Base Constructor");
    }
}

class Derived extends Base {
    static { System.out.println("2. Derived Static Block"); }

    { System.out.println("5. Derived IIB"); }

    Derived() {
        super();
        System.out.println("6. Derived Constructor");
    }

    public static void main(String[] args) {
        System.out.println("--- Instantiation 1 ---");
        new Derived();

        System.out.println("--- Instantiation 2 ---");
        new Derived();
    }
}

```

#### Output Trace:

```
1. Base Static Block
2. Derived Static Block
--- Instantiation 1 ---
3. Base IIB
4. Base Constructor
5. Derived IIB
6. Derived Constructor
--- Instantiation 2 ---
3. Base IIB
4. Base Constructor
5. Derived IIB
6. Derived Constructor

```

_(Notice that in Instantiation 2, static blocks **do not execute again**, because the class is already loaded in Metaspace)._

### 11. Comparison: Constructor vs. Method

| Dimension             | Constructor (`<init>`)                                      | Method                                                                     |
| --------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Purpose**           | Initializes state during instantiation                      | Defines behavior and operations on an object                               |
| **Return Type**       | **None** (Declaring any return type turns it into a method) | **Mandatory** (Must specify primitive, reference, or `void`)               |
| **Name**              | **Must strictly match** the enclosing class name            | Can be any valid identifier (standard camelCase)                           |
| **Invocation**        | Invoked **implicitly** via `new` or `this()` / `super()`    | Invoked **explicitly** via `obj.method()` or `Class.method()`              |
| **Inheritance**       | **Not inherited** by subclasses                             | Inherited by subclasses (subject to access levels)                         |
| **Polymorphism**      | Cannot be overridden (no virtual dispatch)                  | Can be overridden if non-static, non-final, non-private                    |
| **Keywords Allowed**  | `public`, `protected`, `private`                            | Access modifiers + `static`, `final`, `abstract`, `synchronized`, `native` |
| **Default Provision** | Synthesized by compiler if zero constructors written        | **Never** synthesized by compiler                                          |

### 12. High-Yield CDAC Exam Traps & Interview Questions

- **Q1: Can a constructor be declared `private`? What is the practical architectural use?**
  - _Answer:_ **Yes.** A private constructor prevents external instantiation via `new`.

  - _Common use cases:_
    1. **Singleton Pattern:** Restricting instantiation to a single static instance.

    2. **Utility / Factory Classes:** Classes containing only static methods (e.g., `java.lang.Math`, `java.util.Collections`) use a private constructor so they cannot be instantiated.

    3. **Enforcing Builder Pattern:** Forcing creation through a designated static builder.

- **Q2: What happens if a superclass does not have a no-argument constructor, and the subclass does not use `super(...)` explicitly?**
  - _Answer:_ **Compilation Error.** The compiler automatically tries to insert `super();` as the first line of the subclass constructor. If the superclass only has parameterized constructors, `super()` does not exist, and compilation fails. The developer must explicitly invoke a matching superclass constructor: `super(arg);`.

- **Q3: What happens if a constructor throws an exception? Is the object garbage-collected?**
  - _Answer:_ If an exception escapes a constructor, object creation **fails**. The reference is never returned to the caller. However, any resources allocated before the exception may linger until finalization. This pattern is vulnerable to **Finalizer Attacks** in legacy Java (mitigated by declaring classes or methods `final`).

- **Q4: Can you call a subclass method from a superclass constructor? What is the danger?**
  - _Answer:_ **Yes, but it is a severe anti-pattern.** If a superclass constructor calls an overridden method, the **subclass implementation will execute before the subclass fields have been initialized** (they will still hold raw zeros/nulls), leading to bugs or `NullPointerException`.

- **Q5: Can `this()` and `super()` be used together in the same constructor?**
  - _Answer:_ **No.** Both instructions are required to be the **very first statement** of a constructor. Since two statements cannot both be first, they are mutually exclusive. Calling `this()` delegates to an overloaded constructor, which will handle `super()`.
